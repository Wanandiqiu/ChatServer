# 单聊历史消息 — 需求说明

**状态**：draft（brainstorm 产出，待 `/ce-plan`）  
**目标版本**：v0.4.0 或 v0.5.0（与群聊 v0.4.0 可并行规划，本需求不依赖群聊）  
**背景**：ChatServer 当前仅支持在线推送与登录后拉取**未投递**离线消息，缺少 IM 必备的**历史漫游**能力。

---

## Summary

为已登录用户提供与指定好友之间的**分页历史消息查询**，并在 CLI 中可验收。复用现有单聊存储与好友关系校验，不引入群聊、已读回执、多媒体或 Web 网关。

---

## Problem & Outcome

**问题**：用户换终端、重连或想查看更早记录时，只能看到「登录后补发的未读」，无法主动拉取已投递过的历史。

**成功时用户能**：

- 选定一位好友，查看双方最近 N 条单聊记录（时间正序展示）
- 通过游标继续向上翻页（更早的消息）
- 非好友或非法 uid 时收到明确错误，而非空列表或崩溃

---

## Requirements

### 历史查询

- **R1**：已登录用户可向服务端请求与指定 `peer_uid` 的单聊历史；`peer_uid` 须为已注册且与请求方互为好友。
- **R2**：单次响应返回的消息条数有上限（由请求中的 `limit` 指定，服务端设最大上限防止滥用）。
- **R3**：支持**向上翻页**：请求可携带 `before_msg_id`（不含该条及之后更新的消息），返回按 `msg_id` 降序取 `limit` 条后在响应中按**时间/ id 升序**排列，便于客户端直接展示。
- **R4**：无 `before_msg_id` 时表示拉取「最新一页」。
- **R5**：历史范围仅包含当前库中 `chat_message` 已存储的单聊记录；不保证包含已被物理删除的数据（本阶段不做撤回）。

### 与现有能力的关系

- **R6**：历史拉取**不替代**现有离线补发：登录后仍按现逻辑推送 `delivered=0` 消息；历史接口用于任意时刻主动查询。
- **R7**：拉取历史不改变 `delivered` / 已读状态（本阶段无已读模型）。

### 协议与客户端

- **R8**：新增请求/应答消息类型（命名在 plan 阶段定，如 `FETCH_HISTORY_MSG` / `_ACK`），载荷包含 `peer_uid`、`limit`、可选 `before_msg_id`；应答包含 `errcode`、消息列表（至少：`msg_id`、`from_uid`、`to_uid`、`content`、`sent_at`）。
- **R9**：`chat_cli` 增加菜单项：输入好友 `uid` 与可选条数，打印返回的历史记录。
- **R10**：未登录调用历史接口返回 `kNotLoggedIn`（与现登录门禁一致）。

### 验收

- **R11**：双用户注册、互为好友并互发数条消息后，一方通过新接口可拉取到全部已入库记录，且分页连续无重复、无遗漏（在同一 `before_msg_id` 语义下）。
- **R12**：对非好友或不存在 `peer_uid` 请求返回可区分错误码（复用 `kNotFriend` / `kInvalidUid` 或等价语义）。

---

## Scope Boundaries

### In scope

- 单聊（1v1）历史分页查询
- 好友校验、登录门禁
- CLI 演示

### Out of scope（本里程碑明确不做）

- 群聊历史
- 会话列表 / 最近会话摘要接口（可后续单独里程碑）
- 已读回执、未读数
- 消息撤回、编辑、删除
- 全文搜索、按关键词过滤
- 图片/文件/语音等富媒体
- WebSocket / Web 客户端
- 跨设备多端同步协议（除现有挤下线外）

### Deferred（后续里程碑）

- 已读回执与 `delivered` 语义升级（见路线图 v0.5.0+）
- 心跳与重连后增量同步（`last_msg_id`）
- 会话列表 API

---

## Assumptions

- 历史数据继续存于现有 `chat_message` 表结构，不强制引入 `conversation_id`（1v1 可由 `(min_uid,max_uid)` 或双向 `from/to` 查询表达）。
- 学习阶段不要求毫秒级性能；SQLite 分页查询即可。
- 消息 `content` 仍为纯文本。

---

## Success Criteria

1. 文档 `docs/VERSIONS.md` 在发布时增加对应版本章节，描述历史拉取能力与验收步骤。
2. `cmake --build` 通过，`chat_cli` 可完成「加好友 → 发消息 → 拉历史」闭环演示。
3. 错误路径（未登录、非好友、非法 uid）均有稳定 `errcode`，与 `include/ErrCode.hpp` 一致。
